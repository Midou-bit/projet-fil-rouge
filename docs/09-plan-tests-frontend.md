# Plan de tests frontend

## Périmètre et lecture

Ce plan relie les principaux parcours et règles frontend de FRAMEFORGE aux tests Vitest réellement présents. Il n'est pas exhaustif au sens d'une recette navigateur complète : les tests s'exécutent dans `jsdom`, avec les appels réseau et contextes applicatifs simulés lorsque nécessaire.

Validation finale du 22 septembre 2026 :

```bash
cd client
npm run test:coverage -- --maxWorkers=2
```

Résultat observé : **26 fichiers réussis, 118 tests réussis, 0 échec**. Couverture V8 : **58,24 % statements (925/1 588), 59,55 % branches (667/1 120), 41,51 % fonctions (225/542) et 62,26 % lignes (797/1 280)**. Le seuil configuré de 50 % sur les lignes est respecté.

Dans le tableau, « Réussi » signifie que les cas automatisés cités ont réussi lors de cette exécution. Un même identifiant peut regrouper plusieurs cas proches d'un même fichier afin de garder une traçabilité lisible.

## Limites et compléments manuels

Cette suite vérifie les comportements et une partie de la sémantique accessible, mais elle ne remplace pas :

- une recette de bout en bout dans de vrais navigateurs et sur mobile ;
- un audit RGAA complet avec navigation clavier et lecteur d'écran ;
- une vérification visuelle des contrastes, états de focus et animations réduites ;
- un paiement Stripe test avec un compte externe configuré ;
- l'activation et la réception d'événements dans un compte GoatCounter réel.
